# DSH 管家 UI 布局重规划方案（v1 · 2026-09-30）

> 原则：**不推翻重做**。保留顶栏 + 左侧栏骨架、卡片体系、CSS 变量主题、设置页分组导航等已有资产，只做"整合、分组、分层"三件事，分四阶段渐进落地。

---

## 1. 现状诊断

### 1.1 导航入口
- 侧栏 **16 个可见页面**、4 个分组，但分组名与内容错位：「诊断」组里塞了 AI 助手、统计（不是诊断）；「记录」组里混着帮助。
- 高频页与低频页平级平权：「统计」「多 profile」「日志」常年低频，却和「一键部署」「插件市场」占同等视觉权重。
- 页内"指路按钮"泛滥（去市场批量更新 / 去插件页 / 去一键部署 / 先看本体状态）——这是信息架构在打补丁的信号：**功能放错了地方，才需要路标**。

### 1.2 信息密度
- AI 助手页最重：约 **50 处按钮/入口**（顶部与卡内重复的"设置""测试"按钮、通道信息、对话区、导入建议混排）。
- 插件页动作分散：扫描 / 安装 / 安装(.tgz) / 修复 / 清理残留 / 清理备份 / 批量更新(指路) 七八种动作平铺，没有"常用"与"危险"之分。
- DSH 本体页 6 张卡片纵向堆叠（版本与源码 / 更新日志 / 构建记录对比 / 双名单 / 残留 / 问题清单），滚动又长又无锚点。
- **回滚点与数据搬家两页功能重叠**（backup.create ≈ data.backup；backup.apply ≈ data.restore），用户不知道该去哪页做备份。

### 1.3 视觉层级
- 按钮只有样式之分（primary / sm / ghost），没有**频率与风险之分**：卸载、清理残留这类低频高危动作和"刷新"长得一样显眼。
- 卡片标题是唯一层级锚点，卡片之间没有分组容器，一页 4-6 张卡就是一屏流水账。

### 1.4 响应式
- 全站仅 3 个断点（860 / 900 / 1100px），且只处理设置页和市场卡片列数；窗口调窄时侧栏挤压内容区，没有折叠态。
- 无底部状态栏：服务地址、当前版本、最近一次任务结果散落在各页，缺一个"永远可见"的归宿。

### 1.5 改进方向（一句话版）
导航从"16 页平铺"收敛为"**6 大区 + 2 个次级页签**"；页内按钮按"主操作 1 个 + 次操作一组 + 危险操作收进更多菜单"分层；复用设置页的分组导航模式治理重灾区。

## 2. 信息架构

### 2.1 页面收敛映射（16 → 9）

```
现页面                        →  新归属
─────────────────────────────────────────────────────
总览                          →  ① 总览（保持）
一键部署                      →  ② 部署（保持，首次用户主入口）
插件市场 + 插件               →  ③ 插件中心（页签：已装 | 市场 | 维护）
DSH 本体 + 运行状态           →  ④ DSH 本体（页签：状态 | 更新 | 服务）
回滚点 + 数据搬家 + 日志      →  ⑤ 备份与恢复（页签：回滚点 | 搬家 | 日志）
体检报告 + 统计               →  ⑥ 体检（页签：报告 | 运维统计）
AI 助手                       →  ⑦ AI 助手（保持，内部精简）
帮助                          →  ⑧ 帮助（保持）
设置                          →  ⑨ 设置（保持，已有分组导航）＋收纳「多 profile」
```

### 2.2 分组与优先级

```
侧栏结构（分组名按用户视角重命名）：

┌─ 侧栏 ──────────────┐
│ 【开始】             │  ← 高频：装好、用起来
│   总览               │
│   一键部署           │
│ 【使用】             │  ← 高频：日常操作
│   插件中心           │
│   DSH 本体           │
│   AI 助手            │
│ 【保障】             │  ← 中频：出事才来
│   体检               │
│   备份与恢复         │
│ 【更多】             │  ← 低频
│   帮助               │
│   ──────────         │
│   设置（底部固定）   │
└──────────────────────┘
```

### 2.3 合并逻辑要点
- **插件中心**：合并后"市场"是发现入口、"已装"是管理入口、"维护"收纳修复/清理残留/离线安装三个低频动作；批量更新按钮放在市场页顶部（发现新版的地方就是发起更新的地方）。
- **DSH 本体**：版本/更新/构建记录归"更新"页签；启停/重启/端口归"服务"页签；状态摘要与问题清单留"状态"页签。原"完成更新 vs 更新本体"二选一的困惑在合并页内用**单一主按钮**（有新版→"更新"，更新中断→"完成更新"）解决。
- **备份与恢复**：三页合一后，"创建回滚点"是唯一主按钮；校验/预览/还原是行内次级按钮；搬家（导出/导入/还原）独立页签避免与回滚点混淆。
- **多 profile**：从顶级导航降级为设置里的一个分组（低频 + 属于配置性质）。

## 3. 主框架布局

### 3.1 整体骨架（保留现有 grid，新增两块）

```
┌────────────────────────────────────────────────────────────┐
│ 顶栏 56px：品牌 | DSH● 服务● | …  [主题] [刷新] [进入 DSH] │  ← 保持
├──────────┬─────────────────────────────────────────┬───────┤
│ 侧栏 216px│  内容区                                 │       │
│ (可折叠   │  ┌ 页头：标题+副标题 | 页级工具按钮组 ┐  │       │
│  64px     │  ├─────────────────────────────────────┤  │       │
│  图标态)  │  │ 页签行（合并页才有）                │  │       │
│           │  ├─────────────────────────────────────┤  │       │
│           │  │ 卡片流（max-width 1080px 居中）     │  │       │
│           │  └─────────────────────────────────────┘  │       │
├──────────┴─────────────────────────────────────────┴───────┤
│ 状态栏 28px：v2.0.0-rc.4 · http://127.0.0.1:8731 · 空闲/任务名 · 最近备份 3h 前 │  ← 新增
└────────────────────────────────────────────────────────────┘
```

### 3.2 各区职责
- **导航区**：只放页面跳转 + 徽标（可更新/异常计数）；侧栏支持折叠为图标态（悬停出 tooltip），窄窗口自动折叠。
- **内容区**：`max-width: 1080px` 居中 + 两侧留白；一屏最多呈现 **1 个主操作 + 2-3 张卡片**，其余靠页签或折叠分组。
- **工具栏**：统一用现有 `page-head .page-tools` —— 页级按钮只放 2 个以内（1 主 1 次）；行级按钮跟行走；低频高危动作收进「⋯ 更多」下拉。
- **状态栏**（新增）：服务地址（固定 8731 后这里正好展示）、版本号、任务进行中指示（点击展开进度面板）、最近回滚点时间。替代部分散落的 kv 信息。

### 3.3 栅格 / 间距 / 留白
- 8px 基准：卡片内边距 16px、卡片间距 12px、区块间距 24px、页头下边距 20px。
- 卡片双列栅格 `repeat(auto-fit, minmax(340px, 1fr))`，窄窗口自动降单列（替代现在固定单列长滚动）。
- 主操作区（页头下方或首卡顶部）与内容之间留 20px 呼吸位，避免按钮贴内容。

## 5. 适配与规范

### 5.1 响应式断点（新增 2 档，保留现有 3 档）
| 宽度 | 布局 |
|---|---|
| ≥1280px | 侧栏全宽 + 卡片双列 |
| 900-1280px | 侧栏全宽 + 卡片单列（现状） |
| 640-900px | **侧栏折叠为 64px 图标态**（新增） |
| <640px | 侧栏转为汉堡抽屉；顶栏徽标收进状态栏（新增，移动端兜底） |

### 5.2 组件与间距规范
- 按钮 3 级语义：`primary`（每页≤1 个主操作）、`default`（次操作）、`danger-ghost`（卸载/清理/还原，红描边 + 确认弹窗）。
- 行内操作统一放 `.row-actions`（已有），超过 2 个动作收 ⋯。
- 间距 token：`--sp-1:4px / --sp-2:8px / --sp-3:12px / --sp-4:16px / --sp-6:24px`，禁止页面内随手写 margin。

### 5.3 字体与配色层级
- 字号 4 级：页头 18px/600 · 卡片题 13px/600 · 正文 13px/400 · 辅助 12.5px/`--text-3`。
- 配色沿用现有 CSS 变量，新增语义色：`--ok / --warn / --err / --info`（部分已有，统一命名），徽标与问题清单只用语义色，不引入新色相。

### 5.4 可访问性
- 所有可点元素补 `:focus-visible` 焦点环；页签组件复用设置页现成的 `role="tablist"/tab` 写法。
- 危险操作确认弹窗焦点落在"取消"上；toast 增加图标区分 ok/err（不只靠颜色）。
- 保持现有 `prefers-reduced-motion` 支持；对比度按 WCAG AA（正文 ≥4.5:1）抽查深浅两主题。

## 6. 落地路径（四阶段，每阶段可独立发版）

### 阶段一：止血（1 次发版，改动最小）
- **范围**：只动 client.ts 渲染层——AI 页去重（顶部/卡内重复按钮合并）、插件页与本体页动作按"主/次/危险"分层（危险收 ⋯）、删除全部"指路按钮"改为对应页内直达功能；新增状态栏。
- **验证**：现有 UI 测试全绿 + 手工点检清单（每页主按钮唯一）+ 截图审查深浅两主题。

### 阶段二：插件中心合并
- **范围**：插件页 + 市场页合并为页签式；路由保留旧 page id 重定向（书签不炸）；批量更新迁入市场页签。
- **验证**：路由重定向测试 + 插件安装/更新/卸载全流程真机回归。

### 阶段三：本体 + 保障区合并
- **范围**：core+runtime 合并；backups+data+logs 合并；体检报告+统计合并；侧栏分组重命名为四组；多 profile 移入设置。
- **验证**：全量测试 + 高频操作点检（更新/回滚/搬家三条主链路）。

### 阶段四：响应式与规范收尾
- **范围**：侧栏折叠态、窄窗口抽屉、间距 token 全局替换、语义色统一、可访问性修补。
- **验证**：四档宽度截图走查 + 深浅主题对比度抽查 + reduced-motion 回归。

## 7. 功能缺失盘点（本次排查发现的缺口）

| # | 缺失能力 | 现状 | 建议 |
|---|---|---|---|
| 1 | **定时任务管理界面** | 定时体检/备份/查更新只有设置里 3 个数字输入 + 出问题才有提醒卡；没有"下次执行时间、上次结果、手动触发"的页面 | 在「体检」或设置组里加定时任务卡片：三任务各显示上次/下次执行 + 立即运行按钮 |
| 2 | **全局搜索 / 命令面板** | 16 个页面纯靠导航记忆；找不到"清理残留"在哪一页是典型痛点 | 顶栏加 Ctrl+K 搜索：搜页面名 + 动作名直达 |
| 3 | **通知/提醒中心** | 提醒卡片散在总览，公告(notices)是弹窗，看过即走 | 状态栏铃铛聚合：未读提醒/公告/任务失败，点开列表 |
| 4 | **操作审计统一入口** | 写操作记录(auditRows)藏在设置相关页里 | 升格为「备份与恢复」或设置里的"操作历史"页签 |
| 5 | **日志导出** | 体检报告能复制，日志页只能看 | 日志页签加"导出 .txt"按钮（排障发群场景刚需） |
| 6 | **插件版本选择** | 市场只装最新版，无法降级到历史版本 | 市场卡片"安装▾"里列最近 3 个版本 |
| 7 | **移动端** | <900px 只是简单堆叠，顶栏按钮挤压 | 阶段四兜底处理（汉堡导航 + 状态栏收纳） |
| 8 | **键盘快捷键** | 仅个别 role=button | 至少补 Ctrl+K（搜索）、Ctrl+R（刷新）、Esc（关弹窗，已有则确认） |

> 其中 1、2、5 属于"高价值低成本"，建议并入阶段一/二顺手做；3、4、6 记入 backlog 待排期。

## 附：不建议动的部分
- 顶栏 + 侧栏 + 主区三段骨架、CSS 变量主题体系、进度面板/弹窗/toast 三件套、设置页分组导航——都是现成的好底子，本次方案全部保留复用。
- 所有后端动作 API 零改动，本方案纯前端渲染层重组，回滚成本极低。
