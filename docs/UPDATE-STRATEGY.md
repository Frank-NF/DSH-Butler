# 管家自身的更新策略

> 最后更新：2026-09-25　｜　适用版本：DSH管家 2.0.0-rc.1 起

## 一句话

**官网放一份版本清单，客户端定期读它、比版本号，有新版本就提示并给下载入口；不静默替换自己。**

## 为什么不做"自动更新"

1. **这是未签名的程序**。悄悄把自己换掉，用户既没同意、事后也难追溯；出事就是"打不开了"。
2. **Windows 上换不了正在运行的自己**。exe 被自己的进程锁着，只能靠"重启后替换"的旁路
   （临时脚本/重命名），一旦中途失败就留下半个程序 —— 这是最糟的失败形态。
3. **用户没有退路**。手动下载 = 旧版本还在原地，新版本有问题随时退回。

所以策略是：**提示 + 让用户自己装**，把"要不要换"的决定权留给用户。

## 版本清单（发布端）

一个静态 JSON，放在官网上：

```
https://dsh.huilinsh.cn/butler/version.json
```

内容（字段缺省一律按"没有"处理，客户端绝不因为清单写坏就报更新）：

```json
{
  "version": "2.0.0-rc.2",
  "publishedAt": "2026-09-25T12:00:00+08:00",
  "notes": "这一版修了什么、加了什么（一两句，直接显示给用户）",
  "url": "https://dsh.huilinsh.cn/dsh-plugin-butler-2.0.0-rc.2-setup.exe",
  "sha256": "安装包或便携 exe 的 sha256（发布时算，供用户核对）",
  "minVersion": "2.0.0-rc.1"
}
```

服务器上它就是 `/var/www/dsh-butler-site/butler/version.json`（官网静态目录里的一个文件， nginx
直接发盘，不需要额外配置）。安装包按现有规则放在 `/var/www/dsh-updater/`。

## 客户端（接收端）

| 环节     | 做法                                                                    |
| -------- | ----------------------------------------------------------------------- |
| 何时查   | 应用启动后，以及用户在「设置 → 检查管家更新」手动触发                   |
| 缓存     | 6 小时（内存 + `~/.dsh-butler/cache/butler-update.json`），不重复打官网 |
| 版本比较 | 与本体更新同一套 semver 比较（含预发布：`rc.2 > rc.1`）                 |
| 网络失败 | 退回过期缓存并标注原因；连缓存都没有就当"没查到"，**不打扰用户**        |
| 提示     | 「设置」页显示当前版本 / 最新版本 / 更新说明；有新版时给出下载按钮      |
| 不做的事 | 不下载、不替换、不重启 —— 全由用户决定                                  |

对应实现：`src/net/butler-update.ts`（含 5 组单元测试），接口 `GET /api/update/butler`。

## 发一版的步骤

1. 改 `src/version.ts` 里的 `APP_VERSION`；
2. `deno task build`（会顺带把图标写进 exe）；
3. 把产物传到服务器：exe / 安装包 → `/var/www/dsh-updater/`；
4. 更新 `/var/www/dsh-butler-site/butler/version.json`（写新版本号、说明、下载地址、sha256）；
5. 老客户端最多 6 小时后（或用户点「检查更新」时）就会看到提示。

## 还没做的（做之前先想清楚）

- **下载到本地 + 校验 sha256**：可以省用户一次浏览器操作，值得做；但校验失败必须明确报错。
- **静默替换**：见上文三条理由，暂不做。真要做也只在"用户点了确认 + 备份旧 exe +
  重启后替换"的前提下。
- **安装包（NSIS/MSI）**：让卸载、开始菜单、自启项有正规入口；目前只有便携 exe。
- 与官方桌面端的关系：官方已出 Electron 桌面端（见 `docs/research-official-desktop.md`），
  管家不再和它抢"把界面装进窗口"，重心放在官方不管的部分：本体版本管理与更新检查、
  插件/技能管理、托盘与实例管理。
