## 0. 一页结论

**工程健康度 8.5 / 10，安全性 5 / 10。**

项目管理、事务与回滚设计、UI 工程细节都明显高于同类个人项目；但安全边界存在**两个已实测复现的严重缺陷**，
二者可以串成「**任意网页 → 本机任意程序执行**」的链路，建议在对外分发前必修。

最要紧的三件事：

1. **SEC-01（严重）令牌对匿名请求下发** ✅实测 —— 不带任何凭据 `GET /` 就拿到响应头 `butler_token=…`（32 位），
   拿它调 `/api/state/overview`、`/api/jobs` 全部 **200**；不带则 401。令牌因此不构成凭据保护。
2. **SEC-02（严重）版本参数命令注入** ✅实测 —— `cmd /c echo 包@1.0.0&whoami` **真的执行了 whoami**（输出 `ht\niufe`）。
   Deno 只在参数**含空格**时加引号，无空格的 `&`/`|` 会被 cmd.exe 当分隔符，正是「`包名@版本&命令`」的形状。
3. **SEC-03 / SEC-04（高）** 📄 —— bootstrap 的 `url` 无 scheme 白名单（git 参数注入）、`root` 无路径约束（任意 git 仓库可被整体搬移）。

**做对的地方同样突出**：写前回滚点 ＋ 事务日志 ＋ 「只移动不删除」＋ 崩溃恢复，是全项目最扎实的部分；
UI 侧有 `:focus-visible` 焦点圈、Escape 关弹窗、焦点进出弹窗、`prefers-reduced-motion`、完整深色模式、
键盘可达的任务行与 aria 语义 —— 这些在个人项目里很少见。

## 2. 严重问题

### SEC-01 · 严重 · 会话令牌随任意匿名请求下发，认证形同虚设 ✅实测

**位置**：`src/api/server.ts:640-645`（下发函数）、`src/api/server.ts:659-664`（套在**每一条**响应上）、
`src/api/server.ts:237-256`（免鉴权静态入口）、`src/api/server.ts:109-116`（authed 判定）

```ts
// server.ts:640-645
function withSessionCookie(req: Request, res: Response): Response {
  if (readCookie(req, AUTH_COOKIE) === token) return res;   // 只判断“你有没有正确的”，没有就发给你
  const h = new Headers(res.headers);
  h.append("set-cookie", AUTH_COOKIE + "=" + token + "; Path=/; HttpOnly; SameSite=Strict");
  return new Response(res.body, { status: res.status, headers: h });
}
// server.ts:659-664：handle(req).then((res) => withSessionCookie(req, res))  —— 401 与静态资源同样被套用
```

**实测（独立 headless 实例，端口 8731）**：

```
GET /healthz            -> 200 （带 Set-Cookie）
GET /                   -> 200 （带 Set-Cookie）
GET /style.css          -> 200 （带 Set-Cookie）
GET /app.js             -> 200 （带 Set-Cookie）
GET /api/state/overview -> 401 （带 Set-Cookie）   ← 连被拒绝的请求都把令牌发出去了
GET /api/jobs           -> 401 （带 Set-Cookie）
GET /api/state/overview?t=<拿到的令牌> -> 200
```

**影响**：本机任何进程（含低权限用户进程；headless 端口固定 8731）只需一次 `GET /` 读响应头即可取得完整 API 权限；
恶意网页把域名解析到 `127.0.0.1`（DNS rebinding）后，`Set-Cookie` 落在攻击者域名下、后续请求同源，即可读响应 → 完整控制
（装/卸插件、停服、改设置、写注册表自启）。与 SEC-02 组合即是**远程 → 本机任意命令执行**。
服务端全文件**没有任何 Host / Origin / Referer 校验**（已 grep 确认）。

**修复建议**：
1. 只在请求**已携带正确令牌**时下发 cookie（把 Set-Cookie 移进 authed 分支，或用一次性引导码换 cookie）；
2. 加 **Host 白名单**（仅 `127.0.0.1:<port>` / `localhost:<port>`），其它 Host 一律 403 —— 这一条即可单点掐断 rebinding；
3. 写操作强制要求自定义头 `x-butler-token`（浏览器跨源无法自带自定义头），并**下掉 query 令牌**；
4. `/healthz` 只回 `{ok:true}`，不回应用名与版本。

### SEC-02 · 严重 · 版本参数经 `cmd /c` 命令注入 ✅实测

**位置**：`src/domains/plugin/mutate.ts:800-803`（版本未校验拼进 spec）→ `src/domains/plugin/mutate.ts:297-316`（`cmd /c npm install <spec>`）

```ts
// mutate.ts:800-803  —— version 没有任何白名单校验（validPkgName 只管 name）
const version = typeof params.version === "string" && params.version.trim() ? params.version.trim() : "*";
const spec = version === "*" ? name : name + "@" + version;

// mutate.ts:297-314
await run("cmd", ["/c", "npm", "install", spec, "--prefix", profileDir, "--no-audit", "--no-fund", ...]);
```

**实测（隔离探针，只跑 echo/whoami，无副作用）**：

```
args: ['/c','echo','left-pad@1.0.0&whoami']   -> exit=0  输出: left-pad@1.0.0 ⏎ ht\niufe   ← whoami 被执行
args: ['/c','echo','left-pad@1.0.0|whoami']   -> exit=0  输出: ht\niufe                     ← 管道同样生效
args: ['/c','echo','a%USERNAME%b']            -> exit=0  输出: aniufeb                     ← 环境变量也会展开
args: ['/c','echo','x & whoami']              -> exit=0  输出: "x & whoami"                ← 含空格才被加引号，安全
args: ['/c','echo','a^&whoami']               -> exit=0  输出: a&whoami                    ← ^ 被转义
```

**结论**：参数**含空格时** Deno 会加引号从而安全；**不含空格的 `&` / `|` 不加引号**，cmd.exe 照常解释 → 注入成立。
触发路径：`POST /api/jobs {"action":"plugin.install","params":{"name":"left-pad","version":"1.0.0&calc"}}`；
CLI 侧 `router.ts` 的 `--version` 同样不过滤。配合 SEC-01 可远程触发。

**修复建议**：
1. 版本用严格正则白名单：`^[0-9A-Za-z.+-_~]{1,64}$`（禁 `& | % ^ \" < >` 与空白）；
2. 更彻底：不再经 `cmd /c`，改为直接执行 npm 的 `.cmd` 真实路径，或 `node <npm-cli.js>` ＋ 参数数组；
3. 在 `shell.ts` 层加统一防线：参数命中 `& | < > ^ % "` 一律拒绝并记录。

## 3. 高危问题

### SEC-03 · 高 · bootstrap 的 url 未校验 → git 参数注入 📄

**位置**：`src/domains/bootstrap/apply.ts:155`（取值）→ `src/domains/bootstrap/apply.ts:296-305`（`git clone --depth N <url> <root>`）

```ts
const url = params.url?.trim() || BOOTSTRAP_ESTIMATES.repoUrl;            // 155：无 scheme 白名单
const clone = await run("git", ["clone", "--depth", String(depth), url0, root], {...});  // 296
```

url 位于选项区（`--depth 1` 之后），git 的选项解析会接受 `--upload-pack=<cmd>` 这类参数 → 本机命令执行
（能否落地取决于 git 版本与 transport，**未实弹验证**，故标 🔍；但代码事实已确认）。

**修复**：只允许 `https://…` 或 `git@host:…`；并插入 `--` 终止选项解析：`git clone --depth N -- <url> <root>`。

### SEC-04 · 高 · bootstrap 的 root 无路径约束 → 任意 git 仓库被整体搬移 📄

**位置**：`src/domains/bootstrap/apply.ts:190-227`（force 分支）、`apply.ts:464-494`（discard）、`src/util/paths.ts:230-237`

```ts
if (params.force && isDir(root) && isDir(p(root, ".git"))) {          // 216：只要求“是个 git 仓库”
  const dest = p(quarantineStampDir(root, stampOf()), "replaced-by-bootstrap");
  moveSafe(root, dest);                                               // 220：整棵树被移走
}
```

preflight 的「目标目录非空」拦截只对**非 git** 目录生效，所以任意 git 工作树都能过闸；root 允许 UNC／盘根。
虽「只移动不删除、可人工搬回」，但属于可用任意路径触发的高危破坏原语。

**修复**：root 必须位于 `homeDir()` 之下，拒绝 UNC／盘根／系统目录／以 `-` 开头；force 还要求目标确实是 DSH 仓库（含 `apps/cli`）。

## 7. 功能升级建议

### 7.1 近期（1-2 周，修完安全债即可顺手做）

1. **把安全四项修掉并补测试**（SEC-01~04）—— 这是对外分发的前置条件。
2. **让「npm 安装源 / 网络代理」真正生效**（或从界面拿掉）。现状是设置能填、能保存、**装插件时完全没用**，属于「界面撒谎」。
   落地：`pmInstall/pmSync/pmUnlink` 里注入 `npm_config_registry` / `HTTPS_PROXY` 环境变量，或直接加 `--registry <值>`。
3. **日志导出脱敏**（复用 `health.ts:152` 的正则）—— 现在导出的日志里可能带着 DSH 进程令牌。
4. **运行数据自动回收**：给 `plugin-txn` 隔离区与 `jobs` 历史加 TTL（如 30 天），并在设置页给一个「清理历史与隔离区」按钮（附体积显示）。
5. **加 `.gitattributes` ＋ 最小 CI**（push 时跑 `check` / `test` / `lint`）—— 防行尾漂移、防未提交就发布。

### 7.2 中期（产品能力）

6. **安装包与正规卸载入口**（NSIS/MSI）：开始菜单、自启项、卸载器 —— 目前只有便携 exe（`docs/UPDATE-STRATEGY.md` 已列为待办）。
7. **自更新闭环**：下载 ＋ **sha256 校验**（清单里这个字段早就留好了，从未使用），校验失败明确报错；仍不静默替换。
8. **供应链加固**：市场目录签名；安装时提供「跳过安装脚本」开关（`--ignore-scripts`）。
9. **npm 报错翻译器**（本机今天刚踩过）：把 `ERESOLVE` / `EACCES` / `ETIMEDOUT` / 404 等翻成中文人话 ＋ 一键处置。
   今天那次「卸载并安装」失败，用户看到的是一大段 npm 原始堆栈；把根因（peer 版本冲突）和动作（改用宽松解析 / 换版本）直接摆出来，体验会完全不同。
10. **体检报告导出**（Markdown/PDF）：诊断结果可存档、可发给别人求助。
11. **多 profile 管理**：`web` / `desktop` 两个 profile 一键切换 ＋ 分别列出插件与冲突。

### 7.3 远期（差异化）

12. **依赖冲突可视化**：把「谁和谁要的版本不一样」画成图，并给出可执行建议（这是 DSH 插件生态的普遍痛点）。
