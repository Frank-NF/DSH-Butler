# DSH 管家 · 全媒体运营计划

> 版本 v1.0 · 2026-09-26 ｜ 适用对象：DSH 管家（DSH Butler）
> 一句话定位：**给 DeepSeek Harness 用户的本地运维台 —— 装、修、更新、护数据，一个窗口搞定。**

## 一、目标与北极星指标

运营不是发内容，是**让对的人装上并用起来**。所以只认四个数（都可测，不靠感觉）：

| 指标 | 口径 | 3 个月目标 | 怎么测 |
| --- | --- | --- | --- |
| **下载量** | `/butler/*.zip` 的请求数（排除爬虫 UA） | 1,000 | 服务器 nginx 日志按路径统计 |
| **活跃装机** | 每小时读 `/butler/version.json` 的唯一 IP（≈在跑的实例） | 300 | 同上（这是管家自更新的心跳，无需埋点） |
| **GitHub Star** | 仓库 Star 数 | 500 | GitHub API |
| **有效反馈** | Issue + 群反馈被采纳成路线图的条数 | 50 | 人工标记 |

**为什么不用「UV/PV」当北极星**：官网是工具站，看热闹的人多，装的人少。下载与活跃装机才是真信号。

## 二、受众与三句话卖点

**核心受众**（按优先级）：
1. **DSH 重度用户**（已经在用 DeepSeek Harness，被插件与更新折磨过）
2. **AI 工具尝鲜者**（会用 VSCode/Cursor，怕命令行但想要能力）
3. **运维/技术支持**（要给别人装、排障、留证据）

**三句话卖点**（所有渠道统一口径，别自己改）：
1. **不用命令行**：装 DSH、装插件、修问题，全在窗口里点。
2. **出事能退回**：每次改动都留回滚点，动手前先给你看影响。
3. **不采集你**：只监听本机，无遥测；诊断包自动脱敏才允许外发。

## 六、数据看板与复盘

**每周一看**（都可以自动出，不用手工数）：

| 数据 | 来源 |
| --- | --- |
| 下载量 / 活跃装机 | 服务器 nginx 日志（按 `/butler/` 路径 + 排除爬虫 UA） |
| Star / Fork / Issue | GitHub API |
| 各渠道播放与互动 | 各平台后台（手工抄一次） |
| 管家自己的任务统计 | 软件内「诊断 → 统计」页（成功率、失败 TOP） |

**复盘三问**（每周五固定写三行）：
1. 这周哪个内容带来的下载最多？（渠道 × 选题）
2. 用户问得最多的一个问题是什么？→ 变成下周的选题或功能
3. 哪条数据在下滑？下周换什么做法？

## 七、反馈闭环

```
渠道评论 / 群消息 / Issue
        ↓（每条都登记）
  反馈登记表（渠道 / 原话 / 分类 / 是否采纳）
        ↓（每周挑 3 条）
  路线图（docs/FEATURE-ROADMAP）
        ↓（做完）
  发布说明里点名感谢提出者 → 回到渠道回复他
```

**闭环的关键动作**：用户提的问题被做出来后，**回到他留言的那条内容下面回复**。这一步的转化率远高于任何新内容。

## 八、风险与合规

- **不夸大**：不写「一键解决所有问题」，写清能力边界（例如「依赖冲突多数能自动修，少数需手工选版本」）。
- **隐私口径要一致**：官网、README、视频里都要说同一句「只监听本机、不采集使用数据」；讲诊断包时必须说清脱敏机制。
- **开源协议**：MIT 已定；转载与二次分发允许，但要保留 LICENSE。
- **素材版权**：界面截图可自由使用；音乐只用平台曲库；不要用别人的 LOGO 做封面。
- **不承诺时效**：功能演示里避免「永久免费」「永久可用」这类措辞。
