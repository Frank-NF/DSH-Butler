  - 环境体检的「DSH 配置文件」项：0.1.7 起设置由当前 Profile 的插件配置保存、旧 settings.yaml 仅尝试导入一次，settings.yaml 不存在不再告警。

## [1.18.15] - 2026-09-23

### Fixed

- **「完成更新」在某些情况下必然失败**：DSH 官方删掉某个自带包时，`git pull` 只删被跟踪的 `src/`、`package.json`，被 gitignore 的 `lib/` 会留下来。而 tsdown 以 workspace 模式扫 `packages/**` 时**不校验 `package.json` 是否存在**，照样把僵尸 `lib/types/index.js` 当打包入口，于是全量重建报 `[MISSING_EXPORT]`、而 `tsc -b` 却全绿——现象是「更新永远走不完，报错还看不懂」。深度清理新增**孤儿包**识别：目录内无 `package.json` **且** 直接子项全部是已知构建残渣 **且** git 完全不跟踪该目录，三条全中才移入隔离区（只移动、不删除，留有清单可整体还原）
- **「设置保存一直失败，请重试」**（用户报的是「内测声明」点确认永远存不上）：DSH 的配置写入由 `<file>.lock` 独占锁保护，持有进程被强杀时 `finally` 跑不到、锁永久残留，此后**所有**配置写入都会等 2 秒然后超时。实测命中一个 09-18 留下的 `package.json.lock`，卡了 4 天半。新增僵尸写锁清理：只扫浅层、只认「内容能解析成 PID **且**该 PID 确实已不存在」的锁，改名为 `.stale-<时间戳>` 留证据（不删除）；持有者还活着、或读不出 PID，一律不碰。触发点为**管家启动时**与启动服务器时——后者单独不够，因为用户撞上它时服务器往往是开着的
- **重建失败时给出的原因不准**：此前界面上贴的是日志最后 12 行，而那里通常全是无关的瞬时噪音，真正的错误被压在中间。现改为从整份日志里提取真正的报错行（缺导出 / 类型错误 / 写文件被拒 / 找不到模块）

### Changed

- 全量重建撞上 Windows 并发写的瞬时拒绝（`os error 5`）时自动重试，**最多 3 次**；只对瞬时失败重试——日志里出现 `MISSING_EXPORT` / `error TS` 等真错误时立即停止，不让用户白等好几轮
- 官网版本号与文档同步到 1.18.15

## [1.18.14] - 2026-09-19

### Added

- **插件更新先看日志**：点「更新」会先弹出本次更新说明弹窗。优先展示 Release Notes；Release 无正文时自动去仓库取 `CHANGELOG.md` 并截取最新版本段落；两者都没有时，弹窗明确提示**「未发现更新日志」**（不再是空白或一句模糊提示）。插件列表右键菜单「查看更新日志」对所有插件可用
- **客户端 CSP**：`tauri.conf.json` 新增 Content-Security-Policy，只允许加载本机与官方资源，禁止外链脚本/内联脚本/插件对象
- **官网全站安全响应头**：`nosniff`、`X-Frame-Options: DENY`、`Referrer-Policy`、`Permissions-Policy`、`HSTS`、CSP

### Fixed

- **隐私：服务器同步字段不再预填真实地址**。「服务器主机 / 用户 / SSH 私钥 / 远程目录 / DSH 目录 / 更新命令」全部默认为空（此前会带入部署方的真实服务器地址与账号路径）。已清掉本机配置文件中的残留值，并新增单测钉住「默认配置不得泄露任何服务器信息」
- **安全：自更新「验签失败也放行」**：`verify_response_signature` 只在返回 `Some(false)` 时拦截，`None`（无签名头 / 解析失败）被当成通过。现改为必须 `Some(true)` 才放行
- **安全：自更新「没有 SHA256 就跳过校验」**：现改为必须有 `expected_sha256`，缺失即拒绝安装
- **安全：自定义安装源允许明文 http**：公网 http 源可被中间人替换安装包。现仅允许本机回环（`127.0.0.1` / `localhost`）使用 http，其余一律要求 https
- **安全：官网 `/api/manifest/sign` 无需登录即可用私钥签名**：现要求管理员登录 + 单 IP 每分钟 5 次限频，且错误不再回显私钥路径
- **安全：官网 `/api/creators/ledger` 未鉴权**：任何人传任意 `authorId` 都能读到该创作者的收入账。现需登录，且普通用户只能查自己的账

### Changed

- 官网版本号与文档同步到 1.18.14；README 重写（去掉重复章节、修正 UI 库描述、补充安全与隐私章节）

## [1.18.13] - 2026-09-18

- **「完成更新」真正能修好本体**：新增第 2 步**深度清理**——隔离源码树里非当前提交（non-HEAD）的残留文件后再全量重建。此前只做 `git pull` + 构建，残留文件会让 `tsc` 级联报几十条 TS6059/TS6307 而必然失败

## [1.18.6] - 2026-09-12

### Fixed

- **右下角「发现新版本 → 立即安装」点了没反应**：自动更新浮窗把下载下来的文件当成"安装包"直接启动，但自更新通道分发的是**程序自己的裸 exe**——启动它等于又开一个本程序实例，被单实例机制拦下只聚焦了原窗口，所以看起来毫无反应。现改为正确的「替换自身并重启」流程，与设置页「立即更新」共用同一套逻辑
- **更新流程静默失败的老毛病（同类根因）**：旧的替换命令把 `>nul` 并进了 `timeout` 的参数，`timeout` 立即以参数错误退出，**等于延迟根本没发生**，`move` 在程序仍持有 exe 文件锁时执行、覆盖失败，最后重启的还是旧版本（现象就是"点了更新、重启后版本没变"）。现改用 `ping` 做延迟（不受 stdio 重定向影响），并用 `raw_arg` 把整条命令原样交给 cmd，避免参数被二次引号化
- **更新失败不再无提示**：此前安装出错只写控制台，界面上什么也不显示。现在失败会弹出提示，并可在 `%TEMP%\dsh-updater-apply.log` 查看覆盖结果（MOVE_OK / MOVE_FAILED）

### Changed

- 「立即安装」按钮增加进行中状态，避免重复点击

## [1.18.5] - 2026-09-11

### Security

- **移除发行版中所有硬编码的私有服务器信息**（本版可对外分发）：
  - `DSH 本体镜像`不再写死在源码里。原实现把部署方自建的私有中转地址（含账号与路径）编译进 exe，等于随安装包发给每个使用者——既是隐私泄漏，对别人也没用（连不上别人的私有镜像）。现改为纯配置项：**默认留空 = 只用 GitHub origin**，需要镜像的用户在「设置 → DSH 本体镜像」填自己的地址（留空不影响任何原有功能）
  - 界面占位符里的个人路径（`C:\Users\<用户名>\…`）改为通用示例
  - 清理构建过程中残留、且写有本机私有路径的 NSIS 模板副本（未被配置引用，属误提交）

### Added

- **软件内「常见报错修复指南」由 14 条扩充到 26 条**：新增包缺失（`.updater_backups` 残留）、自动更新连坐（反复 cannot resolve 的统一根因）、git SSH 公钥拒绝、`duplicate loader entry id`、preset 丢失、插件缺 `apply` 入口导致 `ctx is not defined`、新版回归 `without inject`、插件装了不在 bundles 启用列表、插件被自动卸载（recovery 台账）、插件已加载但功能无反应（静默失败）、渲染阶段启动失败、版本范围导致被自动升级。全部中英双语、支持关键词搜索。入口：顶部工具栏「扳手」→ 环境修复
- **官网文档新增「故障排查」章节**：26 类故障速查表 + 三个最值得根治的问题详解（自动更新连坐机制、git 通道改写、静默失败三种成因），与软件内指南同源

### Fixed

- **官网 18 条插件仓库链接失效（404）**：对市场目录中 222 条带深路径的仓库链接逐条校验，发现 18 条失效，根因三类——仓库改名（如 `dsh-dag-workflow` → `agent-dag-workflow`）、目录源默认分支写错（写了 `main` 实际是 `master`）、子目录搬迁或删除，另有 2 个仓库已被作者删除。已在服务端加链接修正表纠正，全部核实出新地址并实测可访问；目录由上游定期刷新，修正表随本站长期生效

## [1.18.4] - 2026-09-11

### Fixed

- **卸载插件后 DSH 启动崩溃（cannot resolve profile bundle）**：根因是卸载只删插件目录、没把插件从 profile 加载清单里移除，而 DSH 启动按清单逐项找目录，缺一项就直接报错终止——此前卸载任一已登记进清单的插件，下次启动必然崩溃。现在卸载会同步从 `dsh.profile.bundles` 与 `dependencies` 摘除该插件并写回清单（改前留 `package.json.bak-updater` 备份）
- **插件目录删除不干净**：卸载时若 DSH 服务器正在运行会先自动停止，避免文件被占用导致「删一半」（目录被掏空却仍留在 node_modules），这是上述崩溃的诱因之一；卸载完成后需手动重启服务器

### Added

- **卸载后加载清单自检**：发现「清单登记了但目录找不到」的残留项会记录告警，便于提前排查
- **官网 `/api/updater/latest` 补全顶层 `size_bytes` 透传**：此前只透传了 sha256 漏掉它，导致桌面端拿不到总字节数、下载进度与剩余时间显示失效

## [1.14.1] - 2026-09-10

### Fixed（伪 npm 包名导致安装失败的根因修复）

- **市场目录伪包名拦截（code 128 根因）**：上游目录存在形如 `dsh-web-ui#packages/dsh-skill-explorer` 的 monorepo 子目录条目，桌面端此前把该 `name` 原样当 npm 包名传给 `npm install`，npm 将其解析为 git 依赖（`ssh://git@github.com/null/dsh-web-ui.git`）并执行 `git ls-remote`；GitHub 经本地代理不可达时以晦涩的 `code 128 / unknown git error / Failed to connect ... over proxy 127.0.0.1` 失败。修复分三层：

  - **前端 PluginTable.vue**：一键安装入口对含 `#` 的伪包名先行拦截提示（zh/en 文案 `market.gitRefUnsupported`）
- **官网后端 `/api/plugins` 透传真实 npm 名**：`PluginData` 新增 `npm` 字段（目录源净化后透传，monorepo 子目录引用为 `null`）；`topics` 仅在 npm 名合法时携带真包名（兼容旧桌面端解析）；`batch-check` 对含 `#` 的伪包名直接跳过 registry 查询
