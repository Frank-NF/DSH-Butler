# 产品宣传视频方案（抖音 / 视频号 / 小红书 / B站）

> 画面主体：**真实软件操作录屏 + 动效包装**。不用「截图 + 入场特效」凑时长——
> 录屏必须是**连续真实操作**（真的在点、真的在装、真的在更新），包装层只做强调（光标高亮、
> 局部放大、进度条、数据飞入、转场），不做「假装动起来」的静帧推拉。

---

## 0. 录屏素材规范（四条片子的共同底料）

| 项 | 要求 |
|---|---|
| 录制分辨率 | 2560×1440（后期裁 9:16 仍清晰），窗口拉到 1440×900 以上，UI 缩放 100% |
| 帧率 | 30fps 录制，导出 30fps（B站可 60fps） |
| 录制内容 | 全程真实鼠标轨迹；关闭无关通知；桌面用干净壁纸；主题用**浅色主题**（竖屏里对比度更好） |
| 音频 | 录屏静音；配音后配；BGM 音量 -22～-26dB，人声 -6～-9dB |
| 字幕 | 全程硬字幕，字体**方正清刻本悦宋**，描边 2px，竖屏安全区左右各留 120px |

### 必录的 8 段素材（每段 10～25 秒，多录几遍挑最顺的一条）

1. **冷启动 → 自动扫描**：打开软件，插件列表一条条刷出来（最有「工具感」的开场）
2. **点「更新」弹出更新日志**：完整展示弹窗出现 → 看到本次改了什么 → 点「立即更新」
3. **「未发现更新日志」提示**：故意找一个没有 CHANGELOG 的插件，展示如实提示（**诚实感**，是差异化卖点）
4. **批量更新进度条**：多插件同时更新，进度条 + 完成提示
5. **组合包一键安装**：按行业选包 → 冲突预检 → 一键装齐插件 + MCP + Skill
6. **本体「完成更新」6 步**：点按钮 → 6 个步骤依次打勾 → 完成（最能体现「别人修不好的我能修」）
7. **MCP 服务管理**：连通性预检打勾
8. **安全细节**：设置页的安装源提示（http 仅本机）+ Ed25519 验签标识

## 1. 抖音（9:16 竖屏，1080×1920）

- **时长**：**22～28 秒**（抖音工具类的黄金区间，完播率优先）
- **节奏**：**0.5 秒一切**。前 3 秒必须出「结果」，不能有任何铺垫（没有 Logo 开场、没有自我介绍）
- **脚本结构**：钩子 → 痛点 → 演示 → 反转 → 收尾
  1. `0-3s` **钩子（结果前置）**：直接放「插件全部更新完成」的绿勾满屏画面 + 一句口播
     「你 DSH 里那 30 个插件，我 8 秒全部更新完了。」
  2. `3-7s` **痛点**：快速闪一下手动更新的麻烦（命令行窗口、报错、一个个点）
  3. `7-18s` **演示**：录屏 1+2+4 快剪，倍速 1.5～2×，每一步配 2 个字的动作字幕
     （「扫描」「看日志」「一键更」）
  4. `18-24s` **反转（最有记忆点的一句）**：展示「未发现更新日志」提示
     「它没日志，它也不会骗你有日志。」
  5. `24-28s` **收尾**：Windows 桌面端、官网地址、一句引导
- **文案风格**：**口语、短句、带态度**。用「你」「我」对话感；可以有轻微夸张，但不能吹功能
  - 标题示例：`DSH 插件管家，8 秒更新 30 个插件`
  - 口播示例：`别人修不好的本体更新，它点一下就修好了。`
- **封面**：结果画面 + 4～6 字大字（如「8 秒全更完」），占画面上方 1/3
- **话题**：`#效率工具` `#DeepSeek` `#AI工具` `#插件` `#程序员`
- **发布**：19:00-22:00；评论区置顶下载链接与一句「更新前会自动备份，可以回滚」

## 2. 视频号（9:16 竖屏，1080×1920）

- **时长**：**40～55 秒**（视频号完播容忍度比抖音高，且用户偏「熟人推荐」场景，可以讲清一件事）
- **节奏**：**前快后慢**。前 5 秒抓人，之后放慢到正常速度，留 8 秒做「信任建立」
- **脚本结构**：场景代入 → 演示 → 可信度 → 引导
  1. `0-5s` **场景代入**：「如果你在用 DeepSeek Harness，插件是不是越装越多、越更越乱？」
  2. `5-25s` **演示**：录屏 1→2→6 完整顺序（**不倍速或 1.2×**，视频号用户更吃「看得清」），
     重点把「完成更新」6 步讲清楚
  3. `25-40s` **可信度**（视频号这段最关键）：讲三个「不骗人」的细节
     - 更新前自动备份，可以回滚
     - 没更新日志会明说「未发现更新日志」
     - 目录和自更新都做 Ed25519 验签
  4. `40-55s` **引导**：官网地址 + 「Windows 10/11，独立运行，不用装 Agent」
- **文案风格**：**平实、可信、像在给朋友介绍**。少用感叹号，多用「其实」「你可以」「它是」
  - 标题示例：`管理 DSH 插件，我现在只用这一个工具`
  - 口播示例：`它不会替你决定要不要升级，但会把这次改了什么摆在你看得到的地方。`
- **封面**：软件主界面 + 一句大白话，避免抖音式强刺激
- **发布**：早 7-9 点或晚 20-22 点；配文章链接（官网下载页）比直挂链接更好

## 3. 小红书（3:4 竖版，1080×1440；封面 3:4）

- **时长**：**60～90 秒**（小红书工具类笔记可以长，用户是「带着问题来搜」的）
- **节奏**：**先给结论清单，再逐条演示**。开头必须是一张「3 个理由」的信息卡（1.5 秒），
  后面每段演示 8～12 秒，段与段之间用统一的 0.4 秒「卡片翻页」转场
- **脚本结构**：清单卡 → 逐条演示 → 使用Tips → 收尾
  1. `0-4s` **清单卡**：`装 DSH 插件，我只留了这 1 个工具 / ① 更新前能看到改了什么 ② 组合包一次装齐 ③ 本体坏了能一键修`
  2. `4-40s` **逐条演示**（录屏 2、3、5）：每条前面先出 1 秒小标题卡，再进录屏
  3. `40-70s` **演示「完成更新」6 步**（录屏 6）+ 一句「这步是它跟别家最大的区别」
  4. `70-90s` **Tips + 收尾**：更新前自动备份、MCP 密钥存系统凭据库、官网地址
- **文案风格**：**第一人称、清单体、有轻微个人偏好表达**。可以用「我」「真的」「亲测」，
  但**不夸大**（小红书用户对虚假宣传最敏感）；多用换行和序号
  - 标题示例：`DSH 插件管理｜更新前终于能看到改了什么了😭`
  - 正文示例：`之前最烦的就是点更新不知道更新了啥，这个会先把更新日志弹给你看，没有日志也会直接说「未发现更新日志」，不会装作有。`
- **封面**：3:4，**左文右图**——左边 2 行大字标题，右边软件界面截图；标题 12～16 字
- **话题**：`#效率工具` `#AI工具推荐` `#DeepSeek` `#插件` `#程序员日常` `#桌面软件`
- **发布**：中午 12-13 点或晚 21-23 点；正文里放 3～5 个关键词便于搜索（「DSH 插件」「插件更新」「DeepSeek Harness」）

## 4. B站（16:9 横屏，1920×1080）

- **时长**：**2 分 30 秒 ～ 3 分 30 秒**（B站是「看内容」的场景，太短显得没货）
- **节奏**：**三段式，中间可以慢**。0-15s 结论，15s-2m30s 逐功能演示（正常速度），
  最后 30s 讲原理与边界
- **脚本结构**：结论 → 功能演示 → 原理/边界 → 引导
  1. `0-15s` **结论前置**：一句话讲清它是什么、解决什么，配最华丽的一段操作混剪（1.5×）
  2. `15s-1m10s` **核心功能演示**：扫描 → 插件市场 → **点更新弹更新日志**（重点讲
     Release → CHANGELOG → 「未发现更新日志」三级回退逻辑，这是技术观众最爱的一段）
  3. `1m10s-2m10s` **组合包 + 本体「完成更新」6 步**：讲清为什么要先隔离残留文件再全量重建
     （这里可以放 15 秒的示意图动画说明「残留文件怎么让构建必然失败」）
  4. `2m10s-2m50s` **安全与隐私**（B站观众会认真看这段）：
     Ed25519 验签 fail-closed、SHA256 必校验、安装源强制 https（http 仅本机）、
     客户端 CSP、服务器同步默认留空
  5. `2m50s-3m10s` **边界与下一步**（讲「不做什么」反而涨粉）：只做 Windows/Linux 桌面端、
     不接管 DSH 本体进程、签名密钥待轮换
  6. `3m10s-3m30s` **引导**：官网、GitHub 仓库（开源 MIT）、三连
- **文案风格**：**专业、克制、讲原理**。可以用术语（Ed25519、fail-closed、CSP、non-HEAD 残留文件），
  但每个术语要配一句大白话解释；**不做夸张承诺**
  - 标题示例：`把 DSH 插件管理做成一件顺手的事：更新日志、组合包与「真能修好」的本体更新`
  - 口播示例：`验签失败就拒绝，而不是「没签名就当通过」——前者是安全设计，后者只是装饰。`
- **封面**：16:9，左侧软件界面 + 右侧 8～12 字标题 + 一行小字副标题
- **分区/标签**：`软件 · 电脑软件` / `科技猎手`；标签：`DeepSeek`、`效率工具`、`开源软件`、`Rust`、`Tauri`
- **发布**：周五或周末 19-22 点；简介区放时间戳目录（B站用户会跳看）+ 下载链接 + GitHub 链接

## 6. 制作注意事项（踩过的坑）

1. **录屏必须连贯**：一段操作一镜到底，中途停顿超过 1 秒就重录——观众对「卡住的鼠标」极其敏感。
2. **包装服务于信息**：放大/高亮只用于「这步在干什么」，不要给每个转场都加光效。
3. **数据要真**：插件数量、更新时间等数字从真实界面取，不要用「1000+」这类虚数。
4. **声音优先**：四条片子都要配音（不要只配 BGM）。人声清晰度 > BGM 好不好听。
5. **竖屏安全区**：抖音/视频号底部约 250px 被 UI 遮挡，字幕和操作区不要放在最下方。
6. **合规**：不出现第三方商标误导；说「DeepSeek Harness 生态」而不是暗示官方出品。
